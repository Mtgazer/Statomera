# Architecture

Askora is a static React application with strict TypeScript, Vite and shared CSS tokens. The portable TypeScript build processes bounded CSV, JSON and XLSX locally in browser workers. The DuckDB-Wasm builds remain reference builds. The dataset profile and verified statistical operations supply all analytical evidence. [Phase 1B measurements](PHASE_1B_REPORT.md) · [Phase 2C ingestion contracts](PHASE_2C_REPORT.md)

## Data and execution boundaries

1. React owns the file picker, locale, accessible dataset preview and conversation. Set document language and direction, isolate original labels with bidi markup, format values at presentation time and retain canonical values for computation.
2. The ingestion worker validates file budgets, parses into a staged dataset, retains source text where inference could be lossy, and assigns internal dataset and column IDs. Publish only after validation. Stream or page results and transfer bounded buffers when appropriate.
3. Profile the staged data. Record observed nulls, policy-derived missing values, invalid conversions, and ambiguous schemas separately. Version schema and missing rules so recomputation is traceable.
4. The deterministic bilingual parser is the production authority for question interpretation. It receives the question and active schema metadata, then returns a typed intent, clarification or refusal. Users can also select operations directly. Column aliases preserve the original source labels and ambiguous matches require clarification.
5. The validated analysis router checks the active dataset revision, column IDs, types and bounded parameters against a closed operation list before execution. The profile and verified statistical engines in local workers produce results, counts, exclusions, methods, assumptions and warnings. Replacement invalidates pending work.
6. Localized result templates and chart adapters consume verified evidence. Bounded previews and sampled chart results identify their scope.

Dataset and conversation state are kept in memory. The workspace retires worker jobs on cancellation and replacement. Reopening a dataset requires explicit re-import.

## Dataset ingestion and profiling contract

`csv.ts` owns decoding, record boundaries and delimiter discovery. `normalize.ts` turns parsed CSV into a repeatable rectangular `Dataset` with positional column IDs. `infer.ts` owns cell recognition and column type policy. `profile.ts` combines dataset, missing-marker policy and evidence, then delegates calculation to `summaries.ts` and the existing binary64 mean. `results.tsx` presents the returned `DatasetProfile` with localized values and warnings. Only the worker handles the full decoded file. Phase 2D returns validation statuses for the eight preview rows and capped distinct counts per column. React applies search, filtering and text sorting only to those preview rows. See the [workspace report](PHASE_2D_REPORT.md). Schema overrides are validated against positional IDs and strict conversion rules. Reprofiling opens a fresh worker with the selected file and its original import options. Structured adapters supply bounded native scalar cells through the same dataset contract. JSON and XLSX are loaded on demand in the parser worker. See the [Phase 2C formats and limits](PHASE_2C_REPORT.md) and the [Phase 2A contract and limits](PHASE_2A_REPORT.md#contract-and-interpretation) and the [Phase 2B memory and override results](PHASE_2B_REPORT.md).

Phase 3 builds on the same worker-owned passes. The raw-row equality map yields exact repeat counts and a frequency-of-frequencies summary. A bounded bitmask table records co-missingness for blanks and configured markers. The sorted valid numeric buffer serves both the median and the descriptive distribution and IQR check. React receives aggregates, counts and finding codes for localized explanations. See the [Phase 3 methods and limits](PHASE_3_REPORT.md#methods-and-result-contract).

Phase 4A uses the same short-lived parser worker for on-demand descriptive statistics. A fixed operation and positional column IDs are validated against the inferred or overridden schema from the same file and options. Exact binary64 accumulators and complete-pair eligibility yield one bounded result and its provenance. The worker loads the computation module on demand. See the [Phase 4A methods and evidence](PHASE_4A_REPORT.md).

Phase 4B adds on-demand Student t inference to the same local worker path. Eligibility follows the active schema, paired tests align complete rows, and Welch uses disjoint values of one grouping field. Worker results carry method, counts, effect-size definition, numeric-range warnings and unavailable states. See the [Phase 4B methods and verification](PHASE_4B_REPORT.md).

Phase 4C renders local SVG charts from verified column and inference profiles. Pearson results include bounded complete-pair points or an all-pair density grid. The parser worker performs the grid aggregation. React maps values into plot coordinates and exposes equivalent numeric displays. See the [Phase 4C conventions and verification](PHASE_4C_REPORT.md).

Phase 5A adds an isolated bilingual question parser. It accepts only question text and projected column metadata, returning a resolved intent, clarification, or unsupported reason. The parser has no connection to analysis execution or the workspace at this checkpoint. See the [Phase 5A contract and verification](PHASE_5A_REPORT.md).

Phase 5B binds prepared questions to the active in-memory dataset revision, validates candidates against a closed route list and reuses verified profile and worker evidence. The router invalidates pending work on session changes and defers presentation to Phase 5C. An isolated browser harness exercises the same workspace lifecycle. See the [Phase 5B router and verification](PHASE_5B_REPORT.md).

Phase 5C mounts a localized conversation panel for the published dataset revision. It renders structured evidence from Phase 5B using shared evidence components. The panel owns a bounded in-memory transcript and aborts pending work when its revision is retired or the transcript is cleared. See the [Phase 5C report](PHASE_5C_REPORT.md).

Phase 5D binds workspace rendering to the session’s published snapshot. Clearing a dataset unmounts the result panels and aborts the current conversation. The composer rejects oversized questions before submission. See the [Phase 5D report](PHASE_5D_REPORT.md).

## Optional AI research policy

**AI is optional. Core Askora must work without a model.** The deterministic parser remains authoritative for production intent, and verified profiles and statistical engines are the exclusive source of numerical results. The Phase 6C experiment is complete with a production no-go. Local AI integration is deferred. [Phase 6C closure](PHASE_6C_CLOSURE.md)

Future experiments require separate approval and stay isolated from production imports, dependencies, builds and data paths until they independently pass the gates below. Evaluate candidates for measurable gains in user efficiency, intent understanding, Standard and Egyptian Arabic, ease of use and overall experience.

- Match or exceed the deterministic baseline on the relevant benchmark and correctly reject unsupported requests.
- Preserve strict validation of intent, schema, operation eligibility, revision and parameters. Model output can propose an intent only. Numerical evidence continues to come from the verified engines.
- Demonstrate acceptable latency, memory, download cost and device behavior. Verify privacy compatibility with browser-local processing and Askora's data boundaries.

## Candidate comparison

Primary references reviewed 2026-11-18. Package licenses are indicative for the named project, with pinned dependency, font and model terms to be verified before adoption. Device and performance judgments are design estimates.

| Candidate | Decision and tradeoffs | Reference |
| --- | --- | --- |
| React, MIT | Recommend for composable bilingual screens. DOM and bundle overhead are manageable if preview rows and chart mounts are bounded. RTL comes from semantic HTML and CSS. | TypeScript, Apache-2.0 | Recommend for operation, locale and worker contracts. Types erase at runtime, so validate file, worker and model boundaries. No material browser memory cost from types themselves. | [TypeScript project](https://github.com/microsoft/TypeScript) |
| Vite, MIT | Recommend static builds and worker asset handling. Pin Node and browser targets to the selected release. Verify production worker URLs, Wasm MIME and bundle sizes on Android. | [Vite guide](https://vite.dev/guide/) · [Vite project](https://github.com/vitejs/vite) |
| DuckDB-Wasm, MIT | Recommend for typed SQL, aggregation and native columnar Parquet access. Usually single-threaded. Test selected bundles and Arabic strings, collations and casts explicitly. | [DuckDB-Wasm guide](https://duckdb.org/docs/stable/clients/wasm/overview) · [Troubleshooting](https://duckdb.org/docs/preview/clients/wasm/troubleshoot) · [Project](https://github.com/duckdb/duckdb-wasm) |

| SciPy, BSD-3-Clause | Use as an independent reference for selected engine methods during development. Consider browser use only for a justified method gap and after testing matching Pyodide wheels, numerical tolerance, download and heap footprint. Statistics consume canonical numeric values. | [SciPy stats](https://docs.scipy.org/doc/scipy/reference/stats.html) · [Project](https://github.com/scipy/scipy) |
| ECharts, Apache-2.0, or Plotly.js, MIT | Prefer a modular ECharts trial for core charts with capped marks and canvas/SVG options. Plotly offers useful scientific trace types, with bundles and interaction cost to measure. Benchmark chosen builds on touch devices and test Arabic labels, bidi tooltips, keyboard access and tabular equivalents. | [ECharts project](https://github.com/apache/echarts) · [Plotly.js project](https://github.com/plotly/plotly.js) |
| IndexedDB | Defer raw storage. Can retain sizable structured data asynchronously, but quota, eviction, cleanup and migration are browser-dependent. If adopted, start with opt-in settings or metadata and measure writes, device pressure and failed upgrades. | [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API) |
| Web Workers | Recommend to keep parsing and analytics off the UI thread. Transfer data or send small results to reduce copying. | WebGPU and WebLLM, Apache-2.0 runtime | Deferred, isolated research only. Feature-detect usable adapters and handle device loss. Model weights and context increase storage, GPU memory and first-use downloads. Measure Arabic and mixed-language intent quality and test on actual Android. Review weight licenses separately. Direct and deterministic controls remain available. | [WebGPU](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API) · [WebLLM](https://github.com/mlc-ai/web-llm) |
| PWA platform APIs | Phase 7 candidate. HTTPS, manifest and versioned app-shell caching can improve repeat access. Install affordances and storage behavior vary by browser and Android device. Test update, rollback and offline cache, excluding datasets. | [PWA guide](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps) |

Browser APIs have no application package license. All browser candidates can run without paid compute if their pinned assets fit the host and device limits. Use a restrictive worker CSP and avoid remote extension loading. DuckDB's native Excel extension documents XLSX parsing, while the Wasm extension page describes Excel-like formatting. Prove XLSX behavior in the pinned browser distribution, or evaluate a separately maintained browser XLSX adapter. Similarly verify bundled/local Parquet and JSON dependencies, codecs and types. [Native Excel docs](https://duckdb.org/docs/current/core_extensions/excel) · [Wasm extension docs](https://duckdb.org/docs/api/wasm/extensions)

## Zero-cost deployment

Recommend Cloudflare Pages Free Direct Upload of the portable artifact on the provided subdomain after release approval. Run `npm run build:portable` to generate `dist-portable/` and its static headers. The pinned DuckDB variants exceed the per-file limit even though gzip transfer sizes are smaller. Build locally or with quota-limited CI and use a static artifact. Cloudflare documents 500 builds per month, one concurrent build, a 20-minute build timeout, 20,000 files and 25 MiB per asset, with static traffic free under current documented terms. Avoid Functions and recheck plan terms at release. Configure security headers with the static headers file and smoke-test the actual responses. Fail the build review if any required asset exceeds the limit. Evaluate a smaller bundle or an eligible static host if blocked. Keep optional model downloads out of the core artifact. [Pages limits](https://developers.cloudflare.com/pages/platform/limits/) · [Pricing](https://developers.cloudflare.com/pages/functions/pricing/) · [Headers](https://developers.cloudflare.com/pages/configuration/headers/)

GitHub Pages is a conditional alternative. GitHub Free requires a public repository for Pages, with a 1 GB published site limit and soft bandwidth limit of 100 GB per month. Its commercial SaaS restrictions and header support need review before use. GitHub Actions standard hosted runners are free for public repositories, with plan-specific quotas for private ones. For private CI, verify quotas and spending settings, keep retention small and run locally if free capacity is exhausted. Public application access and repository visibility are separate decisions under the recommended host. [Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) · [Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions)

Verify anonymous access, geographic availability on representative networks, production headers, compressed transfer and uncompressed file sizes, asset loading, and cache behavior. Hosting processes normal web request metadata. Feedback should use explicit submission with a reviewed free channel and documented retention.
