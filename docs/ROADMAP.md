## Phase 7A recommendation

**Core Workflow and Accessibility Readiness** would make the existing flow from local file import to an explainable result reliable for a first-time user on desktop or mobile. Askora already has the analytical methods and evidence for that flow. The immediate gap is completing it confidently across input formats, device sizes and assistive technology before investing in broader reporting or deployment.

- **Scope and benefits.** Exercise CSV, flat JSON and XLSX from import through preview, schema correction, quality findings, a supported question or direct control, and chart or tabular evidence. Improve only friction found in that flow, including discoverability of the preview's scope, eligibility and exclusions, error recovery, visible focus and responsive RTL/LTR behavior. Users should be able to understand what was analyzed, correct a mistaken interpretation and continue after an invalid file or cancellation.
- **Dataset handling and dependencies.** Use the existing workers and verified result contracts. Profile a representative near-limit fixture and repeated imports on a lower-memory device before considering any limit increase. Keep the current file and processing budgets as the initial comparison point. The phase depends on representative fixtures, access to physical Android and iOS devices and a native screen reader, and a compatible WebKit setup or equivalent real Safari coverage. Rendering regressions, worker memory pressure and gaps in device access are the main risks.
- **Suggested verification.** Complete the same bilingual import-to-evidence tasks in Chromium, Firefox and Safari where available. Exercise keyboard-only navigation, visible focus, native screen-reader announcements and narrow layouts in Arabic RTL and English LTR. Verify independently expected values, counts and exclusions. Test malformed and over-limit inputs, cancellation, replacement and worker cleanup without stale evidence. Record elapsed time and any memory proxy with device and fixture details. Confirm same-origin static requests, no dataset uploads or persisted content, and a successful portable build. Log unavailable device or accessibility checks as open release gaps.

Phase 7A is a proposal awaiting explicit approval. The existing Phase 7 reporting and optional PWA work and Phase 8 public release gates remain on the roadmap.
