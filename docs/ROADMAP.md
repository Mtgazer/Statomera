# Development roadmap

Each row is a review boundary. Start the next phase after explicit approval. Use a short-lived task branch from the approved baseline. Checkpoints below are suggested branch names. Commit only verified work, push to an authorized configured remote and review before merging to main. Tag accepted milestones once naming is agreed.

| Phase | Scope and deliverables | Dependencies | Tests and acceptance criteria | Checkpoint and limitations |
| --- | --- | --- | --- | --- |
| 0 | Discovery, requirements matrix, candidate stack, risks, brand, security, testing and written CSV proof plan | Founder references, environment and primary docs | Required docs present, internal links valid, findings distinguish verified observations and proposals | `docs/phase-0`. No measured runtime results. |
| 1 | Run the approved proof first. Establish build, bilingual UI shell, theme tokens, frontend/service decision and baseline CI | Phase 0 approval, selected runtime and approved repo/CI if needed | CSV proof passes or an evidence-backed fallback is reviewed. Build is repeatable and English LTR and Arabic RTL smoke tests pass. | `foundation/phase-1`. Local CI works with hosted CI pending if needed. |
| 2 | Local CSV ingestion, schema, preview and baseline column quality profiles in Phase 2A. Add optional formats individually as approved | Proven worker path and resource budget | Valid data previews correctly, invalid inputs show localized errors, replacement and cancellation remain consistent | `feature/ingestion`. Publish tested formats, encodings and file limits. |
| 3 | Extend the baseline data profiles with deeper quality, readiness and outlier indicators | Ingestion and stable field IDs | Golden fixtures match type and quality outcomes, including ambiguity and sentinels | `feature/profiling`. Semantic meaning and expected gaps may require user input. |
| 4 | Approved descriptive, comparative and inferential analysis operations with provenance | Typed columns, null policy and reference datasets | Outputs meet per-method tolerance and assumption checks and expose denominators and exclusions | `feature/analytics`. Publish supported methods and assumptions. |
| 5A | Bounded bilingual question parsing, schema lookup and typed clarification | Active column metadata and verified statistical contracts | Positive and adversarial fixtures validate resolved operations, required inputs, refusals and deterministic replay. | `feature/phase-5a-intent-engine`. Document supported phrasing. |
| 5B | Route approved intents to verified analysis and return structured evidence and clarification | Phase 5A contract, current dataset revision and operation registry | Only validated resolved intents execute. Equivalent question and direct-control results match. | `feature/phase-5b-analysis-router`. See the [Phase 5B report](PHASE_5B_REPORT.md). |
| 5C | Present bilingual clarification and verified answers | Phase 5B evidence envelopes and session lifecycle | Visible answers trace to verified values and stale responses stay out of the UI. | `feature/phase-5c-conversational-ui`. See the [Phase 5C report](PHASE_5C_REPORT.md). |
| 5D | Harden conversational reliability, accessibility and privacy | Phase 5C workspace and verified worker routes | Browser regressions verify revision clearing, bilingual refusals, keyboard behavior, private execution and bounded workers. | `feature/phase-5d-conversation-hardening`. See the [Phase 5D report](PHASE_5D_REPORT.md). |
| 6A | Polish bilingual question discovery, guidance and evidence presentation | Phase 5D verified workspace | Targeted implementation checks, followed by Antigravity QA | `feature/phase-6a-conversation-ux`. See the [implementation handoff](PHASE_6A_IMPLEMENTATION.md). |
| 6B | Evaluate optional local-AI models, browser runtimes and bilingual intent quality | Phase 6A independent QA checkpoint | Checked model terms and file sizes, synthetic benchmark baseline and a reproducible local-only trial plan | `feature/phase-6b-local-ai-feasibility`. See the [Phase 6B report](PHASE_6B_REPORT.md). Candidate inference requires separate approval and locally available weights. |
| 6 | Optional local model experiment and advanced conversational features | Phase 5 baseline, separately approved model and device scope | Demonstrate measurable language gains and acceptable startup, memory and device behavior before opt-in release | `experiment/local-ai`. Core ships independently if experiment fails. |
| 7 | Charts, reports, complete responsive UI and optional PWA install/cache | Result contract and approved brand assets | Chart/report values match canonical results. Real-device touch, accessibility, caching and update tests pass. | `feature/reporting-pwa`. Installation and offline availability vary by platform. |
| 8 | Hardening, pilot feedback, public static rollout and rollback | Complete release checks, host approval and naming review | Privacy, correctness and device gates pass. Anonymous access, consent flow and rollback verified. Approve public exposure before launch. | `release/public-beta`. Publish host and analytical limitations. |
| Future | Android distribution, advanced cloud AI, accounts, shared workspaces, subscriptions and advanced modeling | Usage evidence, funding as needed and separate approval | Dedicated feasibility, privacy, cost and release gates if approved | Separate branches and milestones. |
